# TagForge：通用核心逻辑、详细方案与技术优势

方法核对日期：2026-10-20；适用场景与宣传文案更新：2026-10-21。依据当前工作区实现，包含未提交改动。本文将 **TagForge 通用核心**作为主体；**PI-seq 过滤与 PB–CB 映射是为 PI-seq 实验定制的扩展方案**。

## 1. 工作的定位与主线

**TagForge 是面向条码编码实验的解析与分子定量框架：将文库结构、条码白名单和 UMI 支持数作为不同层次的证据，依次完成结构解析、身份校正与分子归并，输出具有支持信息的分子明细、稀疏计数及诊断报告。**

核心主线可以写为：

**文库结构定义 → 片段提取 → 逐片段条码校正 → 组合身份与特征注释 → 组内 UMI 聚类 → 分子明细与稀疏计数 → 诊断与报告。**

理解这条主线的关键，是区分三类问题：

| 层次 | 要回答的问题 | 使用的证据 | 产生的结果 |
| --- | --- | --- | --- |
| 结构解析 | 条码和 UMI 在 read 的哪里？ | read 来源、坐标、长度、linker、片段顺序 | 尚未校正的片段与提取方式 |
| 身份校正 | 观测片段属于哪个设计条码？ | 分段白名单、原始位置、允许偏移与错配 | 唯一确定的条码身份或明确的失败状态 |
| 分子归并 | 多条 reads 是否应计为同一个分子？ | 已校正的条码组合、UMI 序列关系、read 支持数 | 代表 UMI、支持 reads 数、原始 UMI 类型数 |

这些层次依次建立约束。先确定条码身份，才能定义 UMI 应在哪个范围内聚类；分子定义建立后，才能进行计数和重复支持诊断。

### 1.1 适用场景：从抗体标签到其他特征条码

TagForge 的通用数据模型是 **身份条码 × 特征条码 × UMI**。身份条码用于区分计数对象，例如细胞条码、样本条码；特征条码对应检测对象，例如抗体标签、sgRNA 或抗原标签；UMI 用于分子归并。因此，通用流程具有从抗体标签向其他特征条码实验扩展的基础。

| 应用场景 | 计数对象与价值 | 当前表述口径 |
| --- | --- | --- |
| 抗体标签定量与组合式条码分析 | 从双端 reads 中解析身份条码、抗体/特征条码和 UMI，生成分子明细及计数 | 当前主要应用；多片段、跨 R1/R2 的布局通过配置表达 |
| 样本标签计数 | 生成细胞 × 样本标签计数，为样本拆分和混样识别提供输入 | 脂质寡核苷酸等标签的潜在适配方向，需按具体结构验证 |
| CRISPR Guide Capture | 生成细胞 × sgRNA 计数，为扰动归属分析提供输入 | 当 sgRNA 身份可通过已知序列和配置直接解析时，具备适配基础 |
| Antigen Capture（抗原捕获） | 生成细胞 × 抗原标签计数，为结合特异性分析提供输入 | 潜在适配方向，需配置和真实数据验证 |
| 启动子 / 报告基因条码 | 对与不同启动子或报告基因设计关联的标签进行 UMI 分子计数 | 面向带 UMI 且设计标签可解析的文库；属于需适配验证的扩展方向，启动子活性或报告基因表达的解释仍由对应实验的下游分析完成 |

应用前提是：输入为当前流程支持的双端 reads；片段可通过坐标或 linker 提取；需要白名单校正的条码具有相应白名单；特征身份可确定；UMI 可以提取。输出计数可用于下游样本拆分、扰动判定或抗原特异性分析，但不把这些下游任务表述为 TagForge 已有的完整功能。

外部实验依据：[脂质连接样本标签](https://www.10xgenomics.com/support/universal-three-prime-gene-expression/documentation/steps/sample-prep/cell-multiplexing-oligo-labeling-for-single-cell-rna-sequencing-protocols)、[CRISPR Guide Capture 特征定义](https://www.10xgenomics.com/support/cn/software/cell-ranger/10.0/analysis/inputs/cr-feature-ref-csv)、[条码化抗原捕获](https://www.10xgenomics.com/support/software/cell-ranger/7.2/getting-started/cr-5p-what-is-antigen-capture)。这些资料支持实验场景及其条码读出的描述，不代表对 TagForge 的兼容性验证。

## 2. 通用流程的详细方案

### 2.1 用声明式配置表达文库结构

对每个片段配置其角色（身份条码、特征条码或 UMI）、来源 read（R1/R2）、长度、固定起点和/或左右 linker，以及条码白名单。一个逻辑条码或 UMI 可以由多个片段构成，并按配置顺序拼接。

因此，通用核心不要求固定的 PB 段数，不要求 UMI 一定连续，也不要求特征条码固定在某条 read 的某个位置。改变支持范围内的文库布局，主要通过调整结构配置完成。

图中采用泛化结构 `R1: L–B1a–L–B1b`、`R2: U1–B2–U2`。其中 B1 是身份条码，B2 是特征条码；这不是 PI-seq 的固定布局。

### 2.2 结构定位与固定坐标互补，但各自受约束

片段支持三种提取方式：

- **固定坐标**：从原始 read 的配置位置截取；开启条码位置偏移校正时，提取附近上下文，供下一步搜索合法窗口。
- **Linker 定位**：依据配置的左、右或单侧 linker 确定片段边界，并检查长度。支持 IUPAC 通配符，以及配置范围内的碱基替换错配；当前 linker 匹配关闭 indel。
- **Linker 后固定位置回退**：配置 `[linker, fixed]` 时，先执行 linker 提取；仅在提取失败后，回到原始 read 的固定坐标提取。回退结果仍必须通过后续条码校正与准入检查。

存在多个左右 linker 配对时，可配置 `length_position` 策略：按目标片段长度筛选，再按距预期位置的距离和 linker 错配数评分；不同片段序列并列最优时拒绝该 linker 判定。当前默认仍为兼容历史行为的 `legacy_shortest`，不能把增强策略描述为默认行为。

另一个容易混淆的边界是：当前回退发生在 **linker 提取失败**时；linker 成功提取但之后白名单校正失败，并不会自动再次尝试固定位置。

**价值：** 将文库结构信息用于定位，并通过明确的回退规则保留可进一步验证的候选；不是对匹配条件无限放宽。提取方式、失败原因和片段成功率可进入质控。

### 2.3 逐片段白名单校正：同时考虑位置与碱基身份

对一个长度为 L 的条码片段，设偏移为 Δ、Hamming 错配数为 d：

1. **原始窗口精确命中白名单，直接接受。** 不继续用其他候选替代这个身份。
2. 否则，在允许的偏移窗口中寻找长度为 L 的片段，并搜索白名单中满足错配上限的序列。位移与错配可按配置独立开启或共同使用。
3. 将候选按以下四元组进行字典序排序：

   `K = (I[Δ ≠ 0] + I[d > 0], |Δ| + d, d, |Δ|)`

   即依次优先：修改类型更少、总修改幅度更小、错配更少、偏移幅度更小。这不是仅按某一个距离寻找最近邻。
4. 最优候选若只对应一个白名单序列，接受该身份；若对应多个不同序列，判为歧义；无合法候选则失败。多个候选位置指向同一条码身份，不属于条码身份歧义。
5. 每个片段校正完成后，再按顺序拼接为完整身份条码或特征条码。

**为什么逐片段校正有意义？** 对组合式条码，分别使用各段已知白名单，就能利用设计先验，无需在程序中展开所有完整条码组合的笛卡尔积白名单。某一段出现错配、偏移或歧义也能单独定位。

这里的组合来自分段规则；当前通用实现并不额外验证所有片段组合是否属于实验上允许的特定组合集合。

### 2.4 统一的数据准入，形成可聚类的有效 read 表

校正身份条码与特征条码后，特征条码映射到注释名称；UMI 各段按指定顺序拼接。有效 read 必须满足提取成功、条码身份有效、特征注释存在（标准特征模式），以及 UMI 各段长度正确且只含 A/C/G/T。

失败原因按优先级归入提取失败、条码歧义、条码无效、注释缺失、UMI 无效等类别。Quick-test 与正式校正共用准入判定函数，便于让预检和全量分析使用一致的判断口径。Quick-test 默认检查开头的 reads，是运行前诊断，不是随机代表性抽样。

有效 read 表建立了统一语义：**这条 read 对应哪个校正后的身份条码、哪个特征，以及哪个观测 UMI。**

### 2.5 在已校正的条码组合内聚合并校正 UMI

条码有已知白名单，而随机 UMI 通常没有可用的设计白名单。因此，UMI 使用不同的纠错依据：

1. 按 `(校正后的身份条码, 特征名称, 原始 UMI)` 聚合 read 支持数。
2. 仅在同一 `(身份条码, 特征名称)` 组内构建 UMI 聚类问题，不跨组归并。
3. 调用 UMI-tools，默认使用 `directional` 方法和距离 1。默认有向连边要求序列距离满足阈值，并满足 `n(parent) ≥ 2 × n(child) − 1`；随后由 UMI-tools 确定簇和代表 UMI。
4. 每个 UMI 簇输出一个分子记录，保存代表 UMI、簇内 read 支持数总和与原始 UMI 类型数。

例如，在一个条码–特征组合内：

- `AAAC: 8 reads`、`AAAT: 1 read`：相差 1 bp，满足丰度条件，默认方法将它们归并为一个分子，支持数为 9。
- 同组的 `GGGC: 3 reads` 与上述 UMI 不连接，形成另一个分子。
- 因此，12 条 reads、3 类原始 UMI，对应 2 个校正后的 UMI 分子。

而在另一个组内，`AAAC: 8 reads` 与 `AAAT: 7 reads` 虽相差 1 bp，但彼此都不满足上述连边丰度关系，在这个仅含两者的例子中保留为 2 个分子。

**价值：** 区别 PCR 重复支持与独立分子证据；同时用丰度条件限制仅凭序列相近产生的归并。准确归并仍取决于文库与 UMI 碰撞等条件，UMI 簇是分析上的分子定义。

### 2.6 先保留分子证据，再汇总为稀疏计数

分子明细不是一个中间总数，而是一张可继续分析的证据表：

`身份条码 | 特征名称 | corrected_umi | reads_count | raw_umi_count`

其中 `raw_umi_count` 是归并前不同 UMI 的数量，不是 reads 数。对每个身份条码 i、特征 j，矩阵元素为：

`M[i,j] = 该组合内校正后 UMI 簇的数量`

每个分子记录对矩阵贡献 1，而不是将 `reads_count` 作为分子数相加。内部优先保留非零条码–特征对的 Parquet 稀疏计数表；按需导出 MTX、TSV 或 Parquet。

**价值：** 同时保留定量结果与重复支持信息，避免只得到一个不可解释的最终矩阵；稀疏形式适合大量条码、特征组合的输出。

### 2.7 在固定分子定义上做降采样诊断

对全深度结果中支持数为 n 的分子，以比例 p 执行 `Binomial(n,p)` 抽样；再统计被检出的分子、单例分子和 reads。当前实现每个比例一次带种子的抽样，并输出计数的解析期望。

- `测序饱和度 = 1 − 分子数 / reads 数`。
- `非单例分子比例 = 至少 2 条 reads 支持的分子数 / 分子数`。

前者衡量 read 层面的重复程度，后者描述分子层面的重复支持覆盖；二者分母不同。它们与提取成功率、校正方式及失败原因等一起进入样本和批次报告。

主要分析保留全深度分子结果。这里的诊断不在各深度重跑条码纠错和 UMI 聚类；按非单例比例选出的诊断抽样比例，也不直接构成测序深度建议。当前 README 部分降采样描述仍提及重复抽样及均值，本文依据实际代码。

## 3. 规模化执行如何保持核心语义

### 3.1 减少重复工作，保留相同判定规则

- 普通 ACGT linker 的精确搜索使用快速字符串查找；需要通配符或错配容忍时使用相应的匹配路径。
- 条码原始窗口精确命中立即返回；校正结果带缓存。
- 对标准 ACGT 白名单且错配上限为 1 的情况，通过生成单碱基替换邻居查集合，而非逐条扫描白名单；每个窗口至多生成 `3L` 个替换候选。其他情况使用相应的通用搜索路径。
- 逐 read 校正轨迹可配置关闭，减少大数据量时的额外输出。

这些是有明确适用条件的实现优化。不能据此直接给出统一的运行加速倍数。

### 3.2 数据分区沿完整分子问题的边界进行

FASTQ 按块读取，提取与条码校正可并行处理 Parquet 片段。默认 UMI 聚合后端使用 DuckDB，将相同 `(身份条码, 特征)` 的数据哈希到同一分桶，避免将同一个 UMI 聚类问题拆到不同 worker。

在距离 1 的支持范围内，先识别 UMI 图的独立连通分量，再将分量交给 UMI-tools；互不连接的部分可以独立计算。批次目标不能成为拆断连通分量的理由，配置的组或分量预算超限时会拒绝运行，而不是破坏聚类边界。

Parquet 减少逐行文本往返，DuckDB 聚合与磁盘溢写降低全量聚合的内存压力；每个 worker 仍需容纳其实际处理的数据，因此应根据数据规模配置资源。

**这项设计的价值是计算分区与分子语义一致：并行化围绕独立问题展开。**

### 3.3 根据依赖状态复用结果，而不是只检查文件存在

阶段检查点纳入相关参数、输入标识、上游结果代次和输出信息；发生影响结果的改变时，对应阶段及下游结果不能直接复用。提取和校正阶段支持恢复已提交的批次；阶段输出通过可恢复的发布流程落到正式位置。

FASTQ 默认使用元数据指纹，可配置完整 SHA256；不能将默认行为描述成所有原始 reads 都经过全量内容哈希。

**价值：** 支持长任务恢复，并减少改了配置、白名单或输入后误用旧结果的风险。Slurm 数组任务与样本/批次报告进一步支持批量运行。

## 4. 优势与先进性该如何讲清楚

最有说服力的总论点是：**TagForge 将文库设计先验、条码身份判定和分子计数语义贯穿整个工作流，并围绕相同语义组织质控、输出和规模化执行。**

| 可直接支撑的设计优势 | 实现依据 | 实际价值 |
| --- | --- | --- |
| 结构与分析逻辑解耦 | R1/R2、片段角色、坐标、linker、顺序、白名单均可配置 | 支持范围内的文库改动通过配置适配，提高复用性 |
| 分段先验驱动的组合条码解析 | 逐段校正后再拼接 | 不需要展开完整组合白名单，错误可定位到片段 |
| 显式的候选评分与歧义拒绝 | 原位精确匹配优先、偏移/错配候选评分、唯一身份约束 | 对可恢复条码与不确定归属使用可解释的不同处理规则 |
| 条码身份与 UMI 证据分层处理 | 已知条码使用白名单；UMI 使用组内距离及丰度 | 按两类序列不同的信息来源确定纠错策略 |
| 以分子及其支持信息为基础的输出 | 代表 UMI、reads_count、raw_umi_count、稀疏计数 | 连接计数、重复支持诊断和下游分析 |
| 不破坏聚类边界的并行组织 | 完整条码组合哈希分桶、独立连通分量处理 | 在独立问题上扩展计算，避免任意分块改变聚类范围 |
| 可解释、可追踪、可恢复的运行 | 统一准入、分段 QC、诊断报告、依赖检查点 | 分辨数据问题与配置问题，支持批量和长任务 |

在宣传中可以说：**结构先验驱动、逐片段可解释校正、分子层面定量、沿分子分组边界扩展计算。**

这些是当前实现能够支持的方法与系统设计优势。UMI 聚类调用 UMI-tools，linker 匹配使用 Cutadapt 与精确匹配路径；对成熟组件的贡献应准确归属。若要进一步声称比其他工具更准确、更快、内存更低，需要在相同数据与资源条件下进行对比验证。当前说明不把设计优势等同于已经证实的普遍性能领先。

## 5. PI-seq 实验定制扩展的位置

PI-seq 与 PB–CB 方案体现通用核心可用于具体实验设计，应在主体介绍之后作为案例或扩展说明：

- **PI-seq 多 PB 过滤**：在通用校正和 UMI 去重之后，按 `(FB, corrected_umi)` 检查跨 PB 的归属；单 PB 直接保留，多 PB 时在优势 PB 的 read 占比严格大于阈值（默认 0.8）时保留该 PB，否则丢弃该组。
- **PB–CB 映射**：在观测 CB 上进行可选的保守纠错和归并，然后依据 read 支持数为每个 PB 选择优势 CB；占比严格大于阈值（默认 0.8）时保留归属。

不将这两个模块与通用条码解析、白名单校正和 UMI 分子计数并列为三个通用产品方向。它们是在共同计算结果上执行实验特定归属规则的方案。

## 6. 可直接复用的宣传简介

TagForge 面向以核酸条码记录实验身份、通过 UMI 进行分子计数的测序实验，适用于抗体标签定量与多片段组合条码分析，尤其适合条码和 UMI 分布于双端 reads、需要结合 linker 定位与位置偏移校正的定制文库。

其通用的“身份条码 × 特征条码 × UMI”框架，还为 Sample Tags、CRISPR Guide Capture、Antigen Capture 及带 UMI 的启动子 / 报告基因条码文库提供适配基础。在完成对应文库的结构配置与数据验证后，可生成细胞 × 样本标签、细胞 × sgRNA、细胞 × 抗原或身份条码 × 设计标签的分子计数，为后续样本拆分、扰动归属和特异性分析提供输入。

通过贯通结构解析、条码校正、UMI 聚类、稀疏计数与质量评估，TagForge 将复杂条码测序数据转化为可追踪的分子证据与定量结果。PI-seq 多 PB 过滤与 PB–CB 映射则作为面向 PI-seq 实验的定制扩展，建立在这一通用核心之上。

**TagForge 通用核心、适用场景与关键判定逻辑。** 第 1 页展示从声明式文库结构、片段提取、逐片段白名单校正，到条码–特征组内 UMI 聚类、分子证据表、稀疏计数及诊断的通用链条；底部展示抗体标签与组合条码、Sample Tags、CRISPR Guide Capture、Antigen Capture 及带 UMI 的启动子 / 报告基因条码文库，突出通用框架的可扩展性；具体扩展应用需按文库结构配置和验证。第 2 页以决策路径展示条码精确命中、偏移与错配候选评分、唯一身份接受及歧义排除；以两组独立的 8:1 和 8:7 read 支持示例解释默认 UMI-tools directional 聚类。下方将工程能力归纳为四组：规模化处理与计算优化、独立分组并行、断点恢复与结果校验、批量运行与过程追踪。第 3 页并列展示 PI-seq 多 PB 过滤与 PB–CB 映射，并说明如何按共享 PB 连接两类输出；两类默认判定均要求优势 read 比例严格大于 0.8。图稿采用宣传用精简版：第一页侧重流程、输出与应用，第二页侧重判定规则与工程能力；完整评分与诊断公式、输出字段保留在本文正文。所有结构、序列、计数均为原理示例。
